## 5. Agent 01 — Platform Foundation & Security Hardening Verification Proofs

Executed 2026-10-18 by AGENT 01 (Platform Foundation and Security Engineer). Scope strictly limited to foundation hardening; no marketing, AI, or WhatsApp inbox surfaces modified.

### 5.1 Controls Implemented & Verified

1. **HTTP Security Headers (`apps/web/src/lib/security/headers.ts`, `apps/web/next.config.mjs`):**
   - HSTS: `max-age=63072000; includeSubDomains; preload` (2 years)
   - Clickjacking prevention: `X-Frame-Options: DENY`
   - MIME sniffing prevention: `X-Content-Type-Options: nosniff`
   - Referrer policy: `Referrer-Policy: strict-origin-when-cross-origin`
   - Legacy XSS auditor disabled: `X-XSS-Protection: 0` (modern standard)
   - DNS prefetch control: `X-DNS-Prefetch-Control: off`
   - Permissions Policy: `camera=(), microphone=(), geolocation=(), payment=(), usb=(), interest-cohort=()`
   - *CSP Note:* Static CSP header intentionally deferred; Next.js 15 App Router requires per-request nonce injection for inline scripts to avoid `unsafe-inline`.

2. **Trusted Tenant Subdomain Resolution (`apps/web/src/middleware.ts`):**
   - Host resolution strictly enforces trust boundaries: `X-Forwarded-Host` only processed when `TRUST_PROXY="true"`.
   - Middleware sets `x-tenant-subdomain` on the forwarded request only after verifying the subdomain is non-reserved and syntactically valid.
   - When no valid subdomain is present, any client-submitted `x-tenant-subdomain` is explicitly deleted, preventing client-side spoofing.

3. **Tenant Isolation & Write-Denial:**
   - Server actions enforce `authorizeTenant` RBAC checking against database membership, rejecting arbitrary client-supplied `tenantId`s.
   - Suspended tenants retain read-only and historical document retrieval access, while all write operations are strictly rejected and audited via `app_tenant_accepts_writes()`.
